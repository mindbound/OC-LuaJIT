# OC-LuaJIT: notes for agents

OC-LuaJIT is a LuaJIT-based CPU architecture for GTNH OpenComputers (Minecraft 1.7.10). It runs machines on our fork of LuaJIT 2.1, pinned at upstream `1ee778a4` (the pin is one file, `native/luajit/upstream.commit`: build-native.sh compiles that commit's tree, checked object by object against its 40 digits, with our twelve patch scripts and its own flags (it drops CFLAGS, CPATH, MAKEFLAGS and the other compiler and make variables on its list from the environment, and takes every directory it is given at its physical path), and refuses a checkout whose HEAD is another, and the jar build refuses a native stamped with another; the toolchain is not pinned; x64, GC64, no FFI, Lua 5.2 compatibility, CHECKHOOK, plus Lua 5.3's `string.pack` and bitwise operators), driven through OpenComputers' own JNLua by a native that `native/build-native.sh` builds, with a full-state serializer for persistence (`serializer/eris_lj.c`) and a timeout watchdog. The authoritative documents are [README.md](README.md) (what the mod is, the Lua dialect, building), [docs/roadmap.md](docs/roadmap.md) (every open and closed row, and the decisions), [docs/jit-guide.md](docs/jit-guide.md) (JIT, DynASM and VM engineering on the fork), [serializer/README.md](serializer/README.md) (the serializer) and [docs/watchdog.md](docs/watchdog.md) (the watchdog). Where this file and they disagree, they win.

Before touching native/luajit/, native/build-native.sh's LuaJIT steps, or anything that changes what the parser, the interpreter or the JIT computes, read docs/jit-guide.md, starting with its Agent checklist. To build another LuaJIT commit or an edit to upstream's files, clone the pristine checkout into scratch and set `OCLJ_LUAJIT_UNPINNED=1` with its own `OCLJ_BUILD` (the native is stamped `unpinned` and never ships); to move the pin itself, follow the guide's 8.2a.

## Conventions for any agent

- Repo files are LF. On Windows, Python writes need `newline=""` (it writes CRLF otherwise), and CR counts are checked by bytes (a Python byte count, `grep -c -U` or `od -c`), never with plain grep or awk, which drop a line-end CR in Git Bash.
- Do not write scripts through shell heredocs that contain backslashes: they collapse silently. Write files with a file tool; patch scripts contain no backslashes at all.
- Prove every new check can fail, on a case that must fail it, before trusting a pass.
- Never write a test that forces a native crash. A crash fix is proved by a black-box census A/B (the same unmodified workload before and after, abnormal exits counted) plus build assertions that the fix is present (JIT guide 11.10).
- Never clear or reuse a results directory: write a fresh one, or move the old one aside.
- Measurement chains longer than a minute run from the main session (nohup plus a monitor); agents get bounded work. Never edit a script that a running chain executes.
- Evidence archives (`bench/runs/<date>-<name>/`) keep md5s of binaries, not the binaries.
- Mark claims [M] measured, [S] read in source, or [I] inferred, and name the run, file or function behind each.
- Never hand-edit files under `build/`: build-native.sh remakes the build copy on every run, from the pin's tree as committed, so an edit there is lost, and an edit in the pristine checkout is never built by a pinned run (P44 in the JIT guide). Experiment in scratch copies.
- The Linux .so that ships is built on glibc 2.28 (AlmaLinux 8) with `OCLJ_GLIBC_MAX=2.28`. A Linux build on a newer distribution, such as Ubuntu, gets its own `OCLJ_BUILD` and never `build/native`, whose `dist/` gradle packages and refuses above the floor. Link and test Linux changes on AlmaLinux 8 too: Ubuntu hides a missing `-pthread` or `-ldl` (JIT guide 7.7, P49).
- From Git Bash, drive WSL through a script file: `MSYS_NO_PATHCONV=1 wsl.exe -d <distro> -- env X=1 sh /mnt/c/<script>`. Variables set or exported on the Git Bash side do not reach the distro, and inline `$` is expanded before the distro's `sh` sees it, so pass variables with `env` and read exit codes from files the script writes (JIT guide P51).
- In shell scripts, never write `VAR=value some_function`: AlmaLinux 8's `/bin/sh` (bash 4.4 in POSIX mode) keeps VAR after a shell function returns, where Git Bash's bash 5.3 and Ubuntu's dash do not. Set and clear it on lines of its own (the glibc round's negative-control fault, roadmap glibc row).
