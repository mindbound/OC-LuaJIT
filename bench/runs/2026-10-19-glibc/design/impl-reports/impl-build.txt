SUMMARY: I've implemented and verified the build side of the glibc round in my 11 files. All of them are LF with CR=0 and pass sh -n.

(a) Linux LINK_EXTRA is now "-static-libgcc -pthread -Wl,--no-undefined". I kept --no-undefined because it held for both variants on both distros, and it is the cheaper, earlier guard: without -pthread the AlmaLinux 8 link fails and names the six pthread functions [M]. I left out -ldl, because the .so imports no dl* symbol.

(b) The ELF import gate sits in step 6, between "# BEGIN/END ELF IMPORT GATE" markers, and runs only on Linux:
- It first checks that readelf actually read the file.
- Any non-weak UND symbol without a version is a BUILD FAIL that names the symbols.
- It reports the highest GLIBC_x.y needed, comparing versions component by component in one awk function.
- With OCLJ_GLIBC_MAX set, a need above the limit, or one outside the GLIBC_x.y family (GCC_x.y, GLIBC_PRIVATE), is a BUILD FAIL that lists the needs, their libraries and up to 12 imports.
- With it unset, it says whether the build is within the release floor 2.28 and carries on.
- Preflight refuses a malformed OCLJ_GLIBC_MAX before the build starts. Set on Windows, it only prints a note.
- The header (EXTERNAL INPUTS, USAGE), the LINK_EXTRA comment and PREREQUISITES 7 (AlmaLinux 8 release build, Ubuntu builds in their own OCLJ_BUILD, git and the fingerprint) are updated.

(c) Every Linux test link now uses TEST_EXTRA="-pthread -ldl" with one shared comment: the 8 runners, plus negative-control.sh's platform case and its six links, which had no tail at all. serializer/Makefile LIBS becomes "-lm -pthread -ldl". It already linked, so this only unifies the spelling.
