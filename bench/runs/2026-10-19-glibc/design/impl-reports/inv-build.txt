SUMMARY: I checked the build side of the glibc round (items 1-5) in AlmaLinux 8 (glibc 2.28, binutils 2.30) and Ubuntu 26.04 (glibc 2.43, binutils 2.46), and all five plan items hold up.

(1) The new Linux link flags are LINK_EXTRA="-static-libgcc -pthread -Wl,--no-undefined". Both variants link with them in both distros. In Alma, the six pthread imports gain versions, libpthread.so.0 becomes NEEDED, and the highest need stays GLIBC_2.17. In Ubuntu the .so is byte-identical to the round-3 one.

(2) Without -pthread, --no-undefined makes the link fail, naming the six pthread functions. The .so does not need -ldl: it imports no dl* symbol, and adding -ldl in Alma only adds a useless NEEDED libdl.so.2.

(3) Two gate commands work the same under binutils 2.30 and 2.46:
- readelf --dyn-syms -W: every non-weak UND name must contain '@'.
- readelf -V: the highest GLIBC_x.y need, found with sort -V.

Both fail first: the trial .so is refused for its six unversioned pthread imports, and the round-3 .so needs GLIBC_2.38. In Alma, adding "-pthread -ldl" to every Linux test link makes the native suites, run-pack, run-bitop and the serializer suite pass; with the current flags shim, security, mem and wd fail to link. In Ubuntu everything links either way.

(4) A PUC Lua 5.3.6 built in Alma (POSIX+DLOPEN, no readline) runs and says 5.3.6. The Ubuntu-built one does not run in Alma.

(5) A Kotlin check in verifyModAssets reads .gnu.version_r, .dynsym and .gnu.version itself, with no binutils. A prototype project running the proposed task code on gradle 9.3.1 with the configuration cache on ran it against 10 natives directories, and every result was as designed.

Exact proposed copies and diffs are in scratch; the repo is untouched (git status is empty, and build/native was only read).

  * GATE COMMANDS, the robust choice [M] (out-failfirst-gates/*, snippet-matrix-3/*; identical verdicts and stdout under binutils 2.30 and 2.46):
(a) readelf --dyn-syms -W, keeping lines where $1 ~ /^[0-9]+:$/, $7=="UND", $5!="WEAK", NF>=8 and $8 !~ /@/. Both readelf versions print versioned UND as name@GLIBC_x.y and unversioned UND with no '@'. That holds whether the versym entry is 1 (objdump prints 'Base') or 0 (objdump prints blank).
(b) The version NEEDS from readelf -V -W: the 'Name:' fields after 'Version needs section', GLIBC_[0-9]+([.][0-9]+)+ only, sort -V, tail -1. Anything else (GCC_*, GLIBC_PRIVATE) is listed separately and refused.

objdump -T is a poor instrument: 2.46 prints UND versions as '(GLIBC_2.34)' in parentheses, and the unversioned marker is 'Base' or blank depending on the file [M]. -W is needed so readelf does not truncate names [S]. On a truncated ELF, readelf exits 0 and prints no symbols, so the gate must first require that UND count > 0 [M] (mutants/trunc).
