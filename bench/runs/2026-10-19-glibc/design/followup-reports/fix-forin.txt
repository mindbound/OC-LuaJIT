SUMMARY: I applied inv-forin's fix to the repo's serializer/tests/forin.lua. It is a test-only fix: the serializer, the fixture and run-forin.sh are unchanged. The fix has two parts.
- diag_suspended takes a new `nojit` argument and calls `jit.off(chunk, true)`. diag_identity, which also feeds the diagblob reference writer, passes true.
- A new gc64_addr filter requires the payload window to read as a GC64 address in both blobs.

I also updated the known-limitations bullet in serializer/README.md that describes the identity check. The code is byte-identical to inv-forin's v-fixed; only the comments are reworded.

Verified [M] in fresh scratch copies of serializer/, built with the repo Makefile against the scratch archives. The final repo file passed diag/4-identity in 1000 of 1000 fresh processes on AlmaLinux 8, 500 of 500 on Ubuntu and 500 of 500 on Windows. The full tests/run-forin.sh passes on all three (31 OK, rc 0).

The same code, checked earlier before a one-line comment edit, passed 2000/2000 on Alma, 2000/2000 on Ubuntu and 1000/1000 on Windows. Same-session pristine controls failed 20/2000 (Alma), 18/2000 (Ubuntu) and 7/1000 (Windows).

The check still fails on a real identity break, on all three platforms:
- In-process pair break (coB over a different table): 20 of 20 fail with 'cannot localise ... 0 candidates'.
- Changed value: 20 of 20 fail with 'body differs from the reference at byte 171'.
- Changed shape: 20 of 20 fail with 'lengths 521 vs 516'.

Each fix part is also shown to be load-bearing:
- Under forced tracing (hotloop=1), the final file passes 20 of 20 on every platform. The same file with `nojit` set to false fails 19, 19 and 20 of 20 (Alma, Ubuntu, Windows).
- A one-line sabotage removing gc64_addr brings back the '2 candidates' failure on a real Ubuntu pair. It also brings back the false accept of a one-ulp difference in a real double.

The fixed reference writer (diagblob) writes a blob matching the committed fixture outside the link payload on all three platforms. The fixture needs no regeneration.

PRODUCT_ISSUE: NONE. The flake was in the test, and it occurs at the same rate on Windows as on Linux: pristine 7/1000 on Windows, 20/2000 on AlmaLinux 8 and 18/2000 on Ubuntu, all in this session [M]. The serializer and the fixture are unchanged; the fixed reference writer reproduces the committed fixture outside the masked link payload on all three platforms [M]. One documentation inaccuracy, already corrected in the README known-limitations bullet, is not a behaviour difference. Thread blobs carry a continuation frame's raw lj_cont_* code address and contpc in its slots. Both are inert because u_thread pass 3 overwrites f-4..f (eris_lj.c:2762-2769) [S][M]. They are platform-independent.
