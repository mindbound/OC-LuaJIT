SUMMARY: The Linux notimer failure is a problem in the test, not the product. The arm's sed patches lj52_wd_fire, the Windows timer callback. That text is still in lj52shim.c on Linux, so the sed and its grep guard both pass, but the code is compiled out (#else LJ52_WD_WIN32, lj52shim.c:2016-2034), and the build that results behaves exactly like the canonical one. Of the watchdog section's arms, only notimer is Windows-only: wdcanon and standinghook reach Linux's compiled code and pass on Windows, Alma and Ubuntu.

The Linux equivalent removes one line of the POSIX condvar thread, lj52_wd_thread:1978, `lj52_wd_inject(M);`. On Alma and Ubuntu that build is caught as intended: W1 passes, W2 is never interrupted, wd_test's alarm ends the run with exit 99, and the summary is never reached. On Windows the same text applies but is compiled out and the arm is not caught, the mirror image of the Alma failure.

I recommend one arm, still named notimer, whose sabotage text is chosen by `case $OCLJ_OS`. The case is followed by a preprocessor guard that refuses a sabotage the host compiles out. I tested the block as written on all three hosts: it is caught every time. With its windows and linux labels swapped it stops with SETUP FAIL, exit 2, on all three, so the guard can fail.

A preprocessor comparison of all 51 sabotaged copies from the last suite run shows notimer is the only shim-text arm compiled out on Linux. The four failing mem arms (rawverdict, nolook, refusalkeeps, noarm) do reach Linux's compiled shim, so their failures are real behaviour differences, not this mistake.

PRODUCT_ISSUE: NONE. On Linux the shipped watchdog enforces deadlines: the canonical wd_test passes 35/0 on AlmaLinux 8 and Ubuntu (run-alma-1 and run-ubuntu-1 wdcanon, and the suite's negctl.log:605-609), and the Windows-text "sabotaged" build is the canonical Linux code, which correctly fired W2 at about 55 ms. The failure is in negative-control.sh: it applies the Windows backend's sabotage text on every host.
