## Trampoline anti-benchmark (reported separately, excluded from geomean)

pcall + vararg-forwarding trampolines per call, as in the OC sandbox spcall wrappers.

- lua5.4: 2.306 s vs lua5.3 2.390 s => 1.04x
- luajit: 0.145 s vs lua5.3 2.390 s => 16.48x
- luajit-joff: 1.034 s vs lua5.3 2.390 s => 2.31x

## Method / caveats

- Timing: `os.clock()` inside each benchmark around the measured kernel only (setup/data generation excluded). On Windows, C `clock()` is wall-clock milliseconds since process start; machine otherwise idle. Resolution ~1 ms.
- Best-of-5 minimum per (VM, benchmark); identical iteration counts and identical Lua sources for every VM.
- Bit ops go through `compat.lua`: LuaJIT uses its built-in `bit` library; 5.3/5.4 use native operators masked to 32 bits, so all VMs produce byte-identical checksums.
- Standalone upper bound: no OpenComputers sandbox, no `debug.sethook` instruction-count throttling, no component-call overhead. In-game deltas will be smaller.
- `trampoline` is deliberately JIT-hostile (every call crosses pcall + vararg forwarding, like OC spcall wrappers) and is excluded from the geomean.

## Addendum: the `strings` anomaly, diagnosed

`strings` (0.25x — LuaJIT 4x *slower* than Lua 5.3, and 10x slower than its own interpreter) is a JIT-pattern pathology, not a string-performance problem. `-jv` tracing shows a side-trace explosion (260+ side traces, repeated interpreter fallbacks): the benchmark's inner loops use `{ string.byte(s, i, i+63) }` (multi-return into a table constructor) and `string.char(unpack(t, 1, 64))` — two patterns LuaJIT's tracer cannot compile, so it endlessly compiles/aborts/side-exits around them.

`strings2.lua` performs the byte-identical workload (same CHECK `12582912-1973928960`) rewritten with 8-wide multi-assignment `string.byte` reads and fixed-arity `string.char` — patterns the JIT compiles cleanly (min of 5 runs):

| VM | strings (naive) | strings2 (idiomatic) | idiomatic speedup vs lua5.3 |
|---|---:|---:|---:|
| lua5.3 | 0.960 | 0.881 | 1.00x |
| lua5.4 | 0.595 | 0.613 | 1.44x |
| luajit | 3.821 | **0.238** | **3.70x** |
| luajit -joff | 0.458 | 0.513 | 1.72x |

Implication for OC-LuaJIT: naive byte-shuffling Lua (a real pattern in OpenOS-style code) can regress under the JIT; the same logic written idiomatically wins. Mitigations for the architecture: document the patterns, consider `jit.off()` on known-pathological stdlib hotspots, and note that geomean figures below are conservative — with `strings2` in place of `strings`, the JIT-on geomean (excl. trampoline) rises from 4.58x to ~6.7x.
