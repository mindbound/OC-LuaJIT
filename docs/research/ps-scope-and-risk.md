## 1. What DONE looks like: the exact contract OC imposes on "eris"

### 1.1 Library surface (Lua-level; OC never uses the Eris C API)
- Global table **`eris`** — every host access is `lua.getGlobal("eris")` (scratchpad/luac_PersistenceAPI.scala:106, 126, 159). Registered at state creation by opening library enum index 10 → `luaL_requiref(L, LUA_ERISLIBNAME, luaopen_eris, 1)` (scratchpad/jnlua.c:456-459, 469); Scala side: `state.openLib(jnlua.LuaState.Library.ERIS)` in every factory (scratchpad/luac_LuaStateFactory.scala:68, 85, 103). Our bridge needs the analog of `LuaState.Library.ERIS`: an open function run at state creation, before sandbox setup, registering global `eris`.
- **`eris.persist(perms, value) -> string`** — called with exactly 2 args, 1 result (`lua.call(2, 1)`, PersistenceAPI.scala:126-137); result read as raw bytes (`lua.toByteArray`, :140). Binary-safe Lua string required.
- **`eris.unpersist(uperms, string) -> value`** — `lua.call(2, 1)` (PersistenceAPI.scala:159-164); the pushed value is then expected at absolute stack index 1 (kernel thread) or 2 (sync-call stack) after `lua.setTop(0)` (luac_NativeLuaArchitecture.scala:360-374).
- **`eris.settings(name, value)`** — setter form only, 2 args 0 results: `settings("spkey", <persistKey>)` and `settings("path", <debugPersistence:boolean>)`, called before *every* persist AND unpersist via `configure()` (PersistenceAPI.scala:105-119). Upstream Eris settings roster for reference: `debug` (bool, default true), `maxrec` (uint, 10000), `path` (bool, false), `spio` (bool, false), `spkey` (string, "__persist") (fnuecke/eris README). We must implement `spkey` and at least accept `path`; the rest can be stubs.
- Host stops the GC around both operations (`lua.gc(STOP)` / `RESTART` in finally, PersistenceAPI.scala:125/148, 158/172) and unlimits memory around save/load (NativeLuaArchitecture.scala:353-355, 398-400). Our serializer may assume GC is stopped, and must support `lua_gc(LUA_GCSTOP)` semantics in the bridge.
- All failures must surface as ordinary catchable Lua errors (see §3), never aborts.

### 1.2 perms/uperms construction — the assumptions that shape the serializer
`PersistenceAPI.initialize()` (scratchpad/luac_PersistenceAPI.scala:15-91):
- Sets global `persistKey` = a host (C) function returning a per-machine random key `"__persist"+UUID` (:13, 17-21); the key is saved/restored via NBT (:95-97, 102) so it is **stable across save/load**, and `configure()` re-feeds it to `settings("spkey", ...)` before every persist *and* unpersist. Requirement: spkey is consulted at both persist and unpersist time and must match keys already baked into persisted metatables.
- Builds `perms` (value→dotted-name) and `uperms` (name→value) by **recursively flattening everything reachable from `_G`** — every *function or table* (`lua.isFunction(-1) || lua.isTable(-1)`, :38), keys sorted for determinism (:57-68), names like `"_G.math.random"`. Asserts no duplicate names (:41); aliases stored once (:43-51).
- Crucially, perms contains **tables** (the `string`, `math`, `component`… library tables themselves) and would happily contain **Lua functions** if any pre-kernel global were implemented in Lua. Confirmed implication: **the serializer must do a perms lookup at every graph node of every type before serializing it by value** — exactly what upstream Eris does (permanent-marker + persist-the-key, per eris.c reference-table mechanism).
- Timing: perms is built by the **last** API initializer (NativeLuaArchitecture.scala:56-57 "Persistence has to go last"), but **before `machine.lua` is loaded/run** (:319-321). Therefore the kernel's `sandbox` table and every closure machine.lua defines are **NOT perms — they are serialized by value** (protos + upvalues + tables), while the stdlib/API values they capture *are* perms. Determinism consequence: the set of globals present at initialize time must be byte-identical (same names) across the save and the load boot, or unpersist fails on unknown permanent — which is exactly OC's sanctioned "mod updated → reboot" behavior.
- Perms flattening enumerates child keys via `lua.toString(key)` then `getField(name)` (:59-71) — pre-kernel global tables must have string-representable, `getField`-addressable keys. Our arch's pre-kernel environment must respect that.

### 1.3 What machine.lua itself requires
- Branches on presence of the `persistKey` global three times: weak proxy-registry metatable `[persistKey and persistKey() or "LuaJ"]` (scratchpad/machine.lua:1061), userdata wrapper `__persist` (:1134), and periodic forced GC in the native path (:1524). Providing the global selects the native/Eris code paths.
- **spkey protocol** as used: metatable field `[spkey]` is a function; at persist time it is called with the object and must return a **closure**, which is persisted *instead of* the object; at unpersist the closure is called with no args and its return value substitutes the object (machine.lua:1055-1068 replaces the whole weak `wrappedUserdata` table with a fresh empty one; :1129-1142 rebuilds userdata proxies from `userdata.save`/`userdata.load` class name + NBT bytes). Upstream Eris semantics to match: metafield `true` = literal persist allowed, `false` = error, function = replacement closure; checked on **tables and userdata**; on unpersist the ref-table slot is **pre-reserved before** calling the closure so reference ordering stays consistent (eris.c special-persistence path). That pre-reservation detail matters: `wrapSingleUserdata` reuse (:1167-1177) and cyclic structures touching proxies depend on it.
- The value persisted at index 1 is **always a suspended coroutine** (the kernel thread created by `lua.newThread()` on the loaded machine.lua chunk, NativeLuaArchitecture.scala:321-322, asserted at save :405); index 2 (sync-call states) is a Lua closure (the one yielded from `invoke`, machine.lua:1094-1100) or a plain table (:410-412). So coroutines are not an exotic case — they are the *root object* of every save.
- The kernel deliberately nils upvalues it cannot persist before yielding (`args = nil -- clear upvalue, avoids trying to persist it`, machine.lua:1086, 1097, 1109, 1534) — the ecosystem already cooperates with a persist-hostile-value model.
- Hooks need no per-thread persistence: the resume loop re-arms `debug.sethook` before every resume (machine.lua:1532, 718). (Side note for the broader port, not the serializer: LuaJIT hook state is global — `hookmask`/`hookf` live in `global_State`, LJ/lj_obj.h:641,655 — machine.lua's per-coroutine `sethook(co, ...)` is a semantic divergence to handle in the architecture work, but it does not add serializer state.)

### 1.4 PRNG / clocks — explicitly NOT the serializer's problem
- OC **replaces** `math.random`/`math.randomseed` with host functions backed by a fresh per-state `java.util.Random` (scratchpad/luac_LuaStateFactory.scala:394-421); that Random is never written to NBT — PRNG state is simply lost on save/load in stock OC. No requirement to persist PRNG state; matching LuaJIT behavior (or bridging to Java the same way) suffices.
- `os.clock` is a host function returning `machine.cpuTime()` (gtnh-oc OSAPI.scala:13-19); `computer.uptime` likewise host-side. Continuity is carried by Machine NBT (`uptime`/`cpuTime` saved at scratchpad/server_machine_Machine.scala:886-887, restored :799-800). Zero serializer involvement.

## 2. The correctness long tail, as a test plan

Each item: what must hold after `persist→unpersist`, and the PUC-Eris precedent.

1. **String interning identity** — two references to the same string collapse to one interned object after restore. Eris relies on `lua_pushlstring` re-interning plus ref-table registration (eris.c). LuaJIT interns *all* strings incl. long ones (LJ/lj_str.c), so identity is automatic if we create strings via the interner. Test: `s1 == s2` and `rawequal` on restored duplicates; a table keyed by a string found by a restored closure.
2. **Shared upvalues between closures** — `debug.upvalueid(f1,1) == debug.upvalueid(f2,1)` preserved. Requires serializing `GCupval` as a first-class ref-counted object (LJ: closures hold *pointers* to upvalue objects, `GCRef uvptr[]`, LJ/lj_obj.h:465-468; closed upvalue = value in the uv, LJ/lj_obj.h:433-446). Test: two closures over one counter; mutate via one after restore, observe via the other. machine.lua's `sandbox` upvalue shared across dozens of closures (e.g. :758, :870) is the production instance.
3. **Open upvalues of a suspended coroutine** — upvalue `v` points at a live stack slot of thread T (uv open, linked at `L->openupval`, LJ/lj_obj.h:702); serialize as (thread-ref, slot-index) and re-link on restore, preserving aliasing between the frame local and every closure capturing it. Eris does this with an upvalue ref/patch table (eris.c u_upval). Test: coroutine suspended inside a loop whose local is captured by a callback stored in a global-reachable table; after restore, resuming must show the callback and the frame observing one variable.
4. **Cycles and shared subtables** — pre-register object before recursing (Eris `registerobject()` pattern). Test: self-referencing tables, `a.b=b; b.a=a`, DAG sharing (two paths to one table remain one table).
5. **Metatables incl. shared and protected** — metatable persisted per table/userdata, recursively, sharing preserved (Eris `p_metatable`). `__metatable`-protected metatables (machine.lua:1145 `__metatable = "userdata"`) must be read via the C-level `lua_getmetatable` equivalent, not the sandboxed one. Test: N tables sharing one metatable → still one; protected mt round-trips.
6. **Weak tables** — PUC Eris has **no `__mode` special-casing**: entries are persisted strongly, the metatable (with `__mode`) is restored, weakness resumes at the next GC (confirmed against eris.c — no `__mode` handling). Match that. OC already routes its dangerous weak table around the serializer via spkey replacement (machine.lua:1055-1068); `proxyCache` (`__mode="v"`, :1229) persists literally and re-collects later. Test: weak-keyed table round-trips; entries collectable after restore.
7. **Userdata via spkey** — the full proxy pattern of §1.3: persist calls mt[spkey](obj) → closure; closure persisted with its upvalues (className, nbt bytes); unpersist calls it, validates returned type, honors pre-reserved ref slot. Test: mock `userdata` API, proxy referenced from two places, cyclically from its own upvalue graph.
8. **Threads referencing threads** — kernel thread's stack contains the bios coroutine `co` as a frame local (machine.lua:1515-1533); user code nests coroutines arbitrarily (sandbox.coroutine bubbling, :843-877). Thread = just another GC object in the ref table. Test: persist thread A suspended while holding suspended thread B created by A; resume both.
9. **The sandbox `_G`** — serialized by value, not reconstructed (§1.2 timing). Test at OC-integration level: boot, define globals + closures in the sandbox, persist, restore, verify they survive while `string.byte` etc. resolved through perms (i.e., restored sandbox's `string.byte` is *the* C function, not a copy).
10. **'value is in perms' at every node** — including as table key, table value, metatable, upvalue value, stack slot of a thread, and the object a spkey closure captures. Test: graph where perms values appear in all positions; plus negative test: unknown-perm name on unpersist errors cleanly.
11. **math.random state** — no persistence required (§1.4). Test only that `math.random` still works after restore and is the perms-resolved host function.
12. **os.clock/uptime continuity** — Machine.scala NBT, out of scope; integration test that values are monotonic across save/load.
13. **Suspended-frame shapes actually reachable in OC** — frames present at yield: `FRAME_LUA`, `FRAME_VARG`, `FRAME_PCALL`/`FRAME_PCALLH` (machine.lua wraps everything in pcall — :1548, :763-768, :690-697), possibly `FRAME_CONT`; **never** `FRAME_C`/`FRAME_CP` at a suspend point per the OC yield protocol (given (c)). Serializer must *verify*, not assume: walk the frame chain (types in LJ/lj_frame.h:14-30; two-slot FR2 layout :33-51), reject on any C frame or non-NULL `cframe` (LJ/lj_obj.h:704) with a clean Lua error. PC values in `FRAME_LUA` slots are absolute pointers into proto bytecode (`frame_pc`, LJ/lj_frame.h:48) → must be relocated to (proto-ref, bc-offset). Test matrix: yield inside pcall inside vararg function inside coroutine.wrap chain; yield with pending xpcall handler; `hitDeadline` path.
14. **Round-trip idempotence oracle** — persist→unpersist→persist. Byte-equality only holds if the writer iterates tables deterministically (hash order differs after rebuild); either write in sorted/insertion-deterministic order to get the cheap byte-equal oracle, or use graph-isomorphism comparison. Decide early; it shapes the fuzz harness.

## 3. Failure containment — the inherited contract, confirmed

Chain verified end-to-end in source:
- Any `lua_error` raised inside `eris.persist` propagates: jnlua wraps every `lua.call` in `lua_pcall` (`JNLUA_PCALL`, scratchpad/jnlua.c:33-38); status `LUA_ERRRUN` → constructs Java `LuaRuntimeException` (jnlua.c:2305-2307, 2333).
- `PersistenceAPI.persist` rethrows after popping (luac_PersistenceAPI.scala:131-137); `NativeLuaArchitecture.save` catches `LuaRuntimeException` and `LuaGcMetamethodException` → logs → **`nbt.removeTag("state")`** (luac_NativeLuaArchitecture.scala:426-433).
- On next load, missing `"state"` int array → empty state stack → `state.nonEmpty` false → `close()` → machine loads **stopped** (scratchpad/server_machine_Machine.scala:760, 774, 815-818). Unpersist-time failures: NativeLuaArchitecture.load wraps into `Exception` (:388-389), caught by Machine.load's `catch Throwable` → `close()` (:808-814).
- Therefore our serializer's whole failure-containment obligation is: **every failure is a Lua error raised via the normal error mechanism (persist side and unpersist side), the lua_State remains closeable afterward, and no path aborts the JVM process.** Given a C implementation inside the state, that means longjmp-safe error paths (no leaked mallocs across `lua_error` — use userdata-buffers or an arena freed by error handler) — this is a real engineering constraint, same one Eris solves.

## 4. Effort model (M1–M5)

Calibration: upstream eris.c is ~2,100–2,800 lines of C, one author, against Lua 5.3 whose internals (explicit `CallInfo` chain) were friendlier than LuaJIT's stack-encoded frames — but our scope is *narrower*: one pinned build (commit 1ee778a4, GC64 x64/arm64, both little-endian → single wire format, no endianness/float portability code, no cross-version compat), no cdata, no C-frame suspends, no debug-info portability requirements. LuaJIT hands us reusable parts Eris didn't have: `lj_bcwrite.c`/`lj_bcread.c` (454+458 lines, LJ tree) already serialize protos (bytecode, constants incl. child protos and template tables, optional debug info).

- **M1 — data-only serializer: tables, strings, numbers, cycles, shared refs, metatables, perms-at-every-node.** ~800–1,200 LOC C; implementable almost entirely against the public C API (lua_next/rawget/getmetatable) so it doubles as the format testbed. Includes format header (magic, format version, build fingerprint = LuaJIT commit + arch + GC64 flag), per-section checksums. *Kill risk:* essentially none structural; the risk is format-design debt (fix the determinism/oracle decision from §2.14 here). *Checkpoint:* property tests over random table graphs — isomorphic restore, shared/cyclic identity, perms substitution both directions; supersedes `string.buffer`-style limits.
- **M2 — protos + Lua closures + upvalue identity (closed upvalues).** ~600–1,000 LOC, reusing lj_bcwrite/lj_bcread per proto with a dedup ref-table so closures sharing a proto still share after restore; `GCupval` as first-class ref-table object. *Kill risk:* proto identity subtleties (bcread creates a fresh proto per read — dedup is on us); template-table constants (`BC_TDUP`) shared vs copied semantics. *Checkpoint:* `debug.upvalueid` equality preserved across restore; closure-pair counter test (§2.2); `string.dump`-loadable functions round-trip.
- **M3 — suspended coroutines.** ~800–1,200 LOC and the majority of debugging time. Serialize `lua_State`: status, stack slots, frame-chain decode (LJ/lj_frame.h types incl. pcall/vararg/cont frames), PC relocation to (proto, offset), `openupval` list re-linking, top/base, and hard *verification* rejects: any `FRAME_C`/`FRAME_CP`, non-NULL `cframe`, currently-running thread (Eris's own restriction: "cannot persist currently running thread"). *Kill risks:* (a) an undocumented invariant of the yield path (what exactly the yield fast-function leaves on the stack) — mitigate by studying `lj_vm_resume`/coroutine.yield VM code paths before writing the format; (b) GC interaction while grafting a half-built thread — mitigate: GC already stopped by host (§1.1), plus build with LuaJIT assertions and GC-stress soak in tests; (c) anything on the stack referencing JIT state — precluded by `jit.flush` before persist (given d), but assert it. *Checkpoint:* yield-inside-pcall-inside-nested-coroutine matrix from §2.13 resumes correctly; a mini-kernel modeled on machine.lua's main loop survives persist mid-`pullSignal`.
- **M4 — spkey/perms protocol polish + OC integration.** ~400–600 LOC C (spkey call protocol with pre-reserved ref slots, `settings`, `path`-style error breadcrumbs) + bridge/Scala work (~500 LOC): register `eris` global at state creation (Library.ERIS analog), PersistenceAPI equivalent, GC stop/restart, byte-array marshaling. *Kill risk:* protocol-order mismatches vs machine.lua's proxy reuse (§1.3) — mitigate by porting Eris's exact unpersist-ordering semantics; also the perms determinism trap (§1.2) — lock the pre-kernel global surface. *Checkpoint:* full dev-world save/load: OpenOS boots, `persist(1)` kernel + `persist(2)` sync-call stack both round-trip; userdata proxies rebuilt; save under `debugPersistence=true` yields readable error paths on injected failures.
- **M5 — hardening/fuzzing.** Mostly test code (1–2k LOC harness): random-program state generators (random graphs + random suspended-coroutine shapes), persist/unpersist/persist oracle, OpenOS boot→persist→restore→boot soak loops, memory-limit boundary tests, error-injection (truncated blobs, flipped bytes → must reject via checksum, never crash), `__gc`-metamethod hostility (OC already fears it: NativeLuaArchitecture.scala:383-387). *Kill risk:* none fatal — this phase converts unknown-unknowns into rejects. *Checkpoint:* N-thousand randomized round-trips with zero crashes and zero silent divergence; week-long simulated save/load churn on real OpenOS images.

**Can two entities (user + AI collaborator) carry it?** The total core is ~3–4k LOC of C — the same order as Eris, which was a one-author project. The pinned-build constraint deletes the categories that make serializers open-ended (portability, version compat, cdata, C frames). The genuinely hard, judgment-heavy part is M3 plus M5's discipline; the AI collaborator is well-suited to the high-volume parts (struct bookkeeping, test-matrix generation, fuzz harnesses, format encode/decode symmetry), the human to in-VM debugging sessions. Verdict: realistic as a months-scale part-time project with M3 as the schedule risk; unrealistic only if M3's runtime verification uncovers OC suspend states that *do* cross C frames (which would contradict given (c) and demand a redesign — surface this early with an M3-first spike that only *walks and validates* live OC frame chains before any serialization code).

## 5. The two failure modes to state honestly

1. **Silent state corruption after restore** — strictly worse than no persistence: a computer that resumes and quietly computes wrong (corrupted upvalue aliasing, off-by-one PC relocation) can damage a player's world-state via robots/components. Mitigations, all cheap relative to the risk: (a) checksums per section + whole-blob, plus the build fingerprint header — refuse on any mismatch; (b) **conservative reject-and-reboot**: any unknown tag, failed type check, un-relinkable upvalue, or unexpected frame type raises a Lua error and rides the existing containment chain (§3) into OC's sanctioned stopped-machine outcome; never "best effort" reconstruction; (c) canary self-test on load: persist a known sentinel structure (string-identity canary, a tiny suspended coroutine) alongside the kernel and verify it behaves exactly right before handing the state back to the Machine; (d) the persist→unpersist→persist oracle in CI as the standing regression tripwire.
2. **Maintenance lock-in to the pinned commit** — the wire format encodes struct-level facts of LuaJIT 1ee778a4/GC64. That is acceptable *by construction*: the format is internal to one shipped natives version; upgrading the natives invalidates saved state and computers reboot — exactly OC's existing precedent (cross-version Eris state was never guaranteed either, and OC already ships the "no natives → no persistent computers" degraded mode, luac_LuaStateFactory.scala:339-341). The obligation is to make it *loud*: fingerprint mismatch → clean reject → reboot, plus a policy decision that any LuaJIT patch we take is a format-version bump. The real cost is opportunity cost (we cannot casually track upstream LuaJIT), which the pinned-build decision already accepted.

# KEY CLAIMS
- [high] OC's entire Eris contract is Lua-level and small: a global 'eris' table (registered via jnlua library index 10 / luaopen_eris) exposing persist(perms,value)->string, unpersist(uperms,string)->value, and settings(name,value) called only with ('spkey',key) and ('path',bool), with GC stopped by the host around both calls; OC never touches the Eris C API.
- [high] The perms table is built by flattening every function AND table reachable from _G before machine.lua runs, so the serializer must do a perms lookup at every graph node of every type, and the kernel's sandbox (with all its closures) is serialized by value, not reconstructed — making determinism of the pre-kernel global surface a hard round-trip requirement.
- [high] The persisted root value is always a suspended coroutine (the kernel thread at stack index 1), so coroutine serialization (M3) is not an edge case but the core deliverable; reachable suspend-time frame shapes include pcall/vararg frames but per OC's yield protocol never C frames — and the serializer must verify this at runtime and reject rather than assume it.
- [high] Failure containment is fully inherited: Lua errors from persist become LuaRuntimeException via jnlua's pcall wrapper, caught in NativeLuaArchitecture.save which removes the 'state' NBT tag, and a missing state tag makes the machine load stopped — so the clone's only obligation is that every failure is a catchable Lua error leaving a closeable state.
- [medium] The effort is one-author scale (~3-4k LOC C total, upstream eris.c is roughly 2-3k lines) with real reuse of lj_bcwrite/lj_bcread for protos, and PRNG/clock state need no persistence (OC backs math.random and os.clock with host functions whose state lives outside Lua or in Machine NBT) — so a user+AI pair can realistically carry M1-M5 over months part-time, with M3 debugging as the honest bottleneck.

CORRECTION: Three crucial nuances, none fatal. (a) The PRNG wording is imprecise for LuaJIT: vanilla LuaJIT's math.random holds its PRNGState INSIDE the Lua heap, as a userdata upvalue of the closure (lib_math.c:131-138, 200-201), and there is a second global PRNG in global_State (lj_obj.h:663); "state lives outside Lua" only becomes true once the port replicates OC's host-function replacement and puts those closures in the permanents table — which OC does by design, so the conclusion survives but the mechanism must be stated as "OC replaces, then no persistence needed", not "LuaJIT state is external". (b) Two M3 landmines the claim does not name: under LJ_FR2/GC64 continuation frames store raw ASM code addresses in stack slots (frame_contf, lj_frame.h:96-97) that change per-run under ASLR and must be symbolically encoded/relocated (tractable: closed set of 7+2); and a coroutine yielded beneath a lj_cont_stitch frame carries a GCtrace reference in a serializable stack slot (vm_x64.dasc:2376-2380 reads the trace from [RB-40]; lj_trace.c:288 blacklists T->traceno=T->link=0 specifically "for cont_stitch"), so save-time canonicalization of JIT artifacts is required. (c) The one-author analogy has an honesty cap: Eris's 2741 lines measure a mature library debugged over years, and Eris's own author refused a LuaJIT port in 2013 (eris issue #4: "there is no LuaJIT support in Eris and there probably never will be", citing low-level struct divergence and re-jitting after unpersist) — there is no completed prior art, so code-size parity supports the LOC estimate but understates calendar risk; saves are additionally coupled to BCDUMP_VERSION and build flags (BE/FR2/FFI/BITOP, lj_bcdump.h:36-48) and to the GC64/dual-number stack layout, which is parity with Eris's PUC-version coupling but must be an explicit format decision.
