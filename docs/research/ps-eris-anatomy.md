## (1) Lua-visible API surface

### Functions (eris_master.c:2656-2661, eris.h:53-150)
| Symbol | Signature | Semantics |
|---|---|---|
| `eris.persist([perms,] value)` | → binary string | perms optional; if 1 arg, an empty perms table is synthesized (eris_master.c:2530-2539). `value` may be any type incl. nil. |
| `eris.unpersist([uperms,] str)` | → any | same optional-perms rule (2566-2576). |
| `eris.settings(name[, value])` | get/set | nil value resets to default (2586-2650). Settings stored in the **registry** keyed by lightuserdata addresses of static strings (291-298, 437-455) — shared across all coroutines of the state. |
| C API | `eris_dump/eris_undump` (writer/reader based), `eris_persist/eris_unpersist` (stack based), `eris_get_setting/eris_set_setting`, `luaopen_eris` | eris.h:53-150 |

### ALL settings (complete list; eris_master.c:294-298, defaults 69-91)
- **`spkey`** (string, default `"__persist"`): name of the metafield controlling special persistence (kPersistKey, line 69).
- **`path`** (bool, default `false`): build human-readable error paths like `root[false]@metatable.__index` (kGeneratePath, 86; README:185-195).
- **`debug`** (bool, default `true`): write Proto debug info — source, lineinfo, locvars, upvalue names (kWriteDebugInformation, 78; p_proto 1206-1244).
- **`maxrec`** (unsigned, default `10000`): max persist/unpersist recursion depth (kMaxComplexity, 91; checked at 2075, 2227).
- **`spio`** (bool, default `false`): pass `lua_Writer`+ud (persist) / `ZIO*` (unpersist) as extra lightuserdata args to `__persist` functions (kPassIOToPersist, 74; used at 1039-1048, 1095-1100).
There is **no** "writable buffer" setting; the string buffer is internal (writer/RBuffer, 2305-2355).

### __persist / spkey protocol — exact semantics (p_special 1013-1075, u_special 1077-1115)
On persist of a **table or userdata**, Eris raw-gets `mt[spkey]`:
- `nil` → default: tables persist literally (key/value pairs via `lua_next`, nil-terminated, then metatable — p_literaltable 904-939); userdata **errors** ("attempt to literally persist userdata", 1073).
- `true` → literal persistence forced; for userdata the memory block is written verbatim (p_literaluserdata 988-995).
- `false` → error "attempt to persist forbidden table" (1070).
- `function` → called as `f(obj)` (or `f(obj, writer, ud)` if spio) with **1 result required, must be a function** (1049-1051); that closure is then persisted **in place of** the object (a `true` flag byte precedes it, 1054). On unpersist the closure is unpersisted and **called with 0 args** (or `f(zio)` if spio, 1095-1100); its single return value **must have the original base type** (table for table, userdata for userdata — type check at 1102-1106). The object's reftable slot is pre-reserved before the call and patched after (1082-1110), so cycles through the special function are an error ("invalid reference #%d", 217-219).
- Any other metafield type → error (1058-1060).

### Permanents protocol (persist_keyed 2124-2167, u_permanent 2200-2222)
Every non-simple value (everything except nil/boolean/lightuserdata/number) is first looked up **as a key** in the perms table (plain `lua_gettable`, so `__index` chains work); if present, tag `ERIS_PERMANENT` + original-type byte + the *perm key* (recursively persisted) are written. On unpersist the key is looked up in uperms and the result must be non-nil **and of the recorded original type** (2207-2218). Perm keys starting with `"__eris."` are reserved (README:111) — used by the **patched stdlib** hooks `eris_permbaselib/corolib/loadlib/iolib/strlib` (eris_master.c:158-171) which register the C **continuation functions** of yieldable stdlib calls (`pcall`, `coroutine.wrap`, ...) so a yielded pcall can be persisted. Identity dedup: every non-simple object gets a refcounted entry; re-occurrences are written as `refid + ERIS_REFERENCE_OFFSET` (2130-2137).

### Lua 5.3 branch deltas (eris_53.c diff)
Integer subtype flag for numbers (`write_lua_Integer`), `LUA_TUPVAL` re-invented as internal tag (removed from 5.3 core), upvalues handled via public `lua_upvaluejoin`/`luaF_initupvals` + `upisopen()` instead of raw `UpVal.v == &u.value`, `lua_KFunction` cast hack for continuations, `base_ci` (callstatus==0) skipped, per-thread `openupval` list now `UpVal.u.open.next`. Wire format is **not** compatible between the two branches; nobody cares (see §4).

## (2) What OC actually uses — the minimal contract

From `scratchpad/luac_PersistenceAPI.scala`, `luac_NativeLuaArchitecture.scala`, `machine.lua`, `jnlua.c`, `luac_LuaStateFactory.scala`:

1. **Library presence**: JNLua opens it as library #10 → `luaopen_eris` under `LUA_ERISLIBNAME` = global **`eris`** (jnlua.c:456-458; LuaStateFactory.scala:68,85,103). OC then calls only `eris.settings`, `eris.persist`, `eris.unpersist` via `lua.getGlobal("eris")` + `getField` (PersistenceAPI.scala:106-116, 126-127, 159-160).
2. **Settings used: only two.** `eris.settings("spkey", persistKey)` where persistKey = `"__persist"+UUID-hex`, randomized per machine and round-tripped through NBT (PersistenceAPI.scala:13, 95-103, 109-111); and `eris.settings("path", Settings.debugPersistence)` (113-116). `debug`, `maxrec`, `spio` stay at defaults. **So spio=false: OC's `__persist` functions are called `f(obj)` on save and `f()` on load — no IO objects.**
3. **Call shape**: `eris.persist(perms, obj)` with perms table explicitly passed (never the 1-arg form), returning a **binary string** fetched as `byte[]` (PersistenceAPI.scala:129-141); `eris.unpersist(uperms, byteArrayString)` returning the value (162-167). GC is stopped around both calls (125, 158) and memory is unlimited during save/load (NativeLuaArchitecture.scala:352-355, 397-400).
4. **Perms content**: OC flattens everything reachable from `_G` (functions and tables, deterministic sorted key order) into perms/uperms at initialize time, stored in the registry as `"perms"`/`"uperms"` (PersistenceAPI.scala:29-89). This is how all Java callbacks (C functions on the native side) become permanents. **Note: OC never relies on Eris's internal `__eris.*` stdlib-continuation perms** for its own API functions — but persisting a coroutine yielded inside `pcall` in PUC Lua does depend on Eris's patched-lib continuation registration; a LuaJIT replacement must make yielded-pcall work by *its own* means (it can, structurally — see §3, errfunc/pcall row).
5. **What gets persisted**: the kernel **thread** at stack index 1 (a `coroutine.create`d machine.lua coroutine, suspended at a plain yield), and optionally one function or table at index 2 for SynchronizedCall/Return (NativeLuaArchitecture.scala:396-413, 357-373). So the replacement must handle: suspended threads, Lua closures + upvalues (shared identity preserved), tables + metatables + cycles, strings, numbers, booleans, nil — plus the spkey-function protocol.
6. **machine.lua's use of the protocol**: it reads the global function `persistKey()` (provided by OC, PersistenceAPI.scala:17-21, *not* by Eris) and installs `[persistKey()] = function(self) ... return function() ... end end` on exactly two metatables: `wrappedUserdataMeta` (machine.lua:1055-1068) and `userdataWrapper` (1129-1142). Both persist-functions return a closure whose upvalues carry the state and which on load must return a **table** (the proxies are tables). Failure to persist is sanctioned: OC catches the Lua error, logs "Could not persist computer", and drops the `state` NBT tag → reboot-on-load (NativeLuaArchitecture.scala:426-433).
7. **jnlua coupling is trivial**: the only other Eris-aware line in the whole native layer strips the `"Lua+Eris "` prefix off `LUA_VERSION` (jnlua.c:183-185). Nothing reads persisted bytes natively.

**Minimal contract**: a global `eris` table with `persist(perms, v)→string`, `unpersist(uperms, s)→v`, `settings("spkey", string)`, `settings("path", bool)` accepted (path may be a no-op), honoring the spkey function protocol with spio=false semantics, perms/uperms substitution with type checking, identity/cycle preservation, and Lua-error failure reporting. That is the whole surface machine.lua + PersistenceAPI touch.

## (4) Wire format

Header: literal `"ERIS"` + `sizeof(lua_Number)` byte + canary double `-1.234567890` + `sizeof(int)` + `sizeof(size_t)` (p_header 2365-2372). Body: stream of little-endian typed records; each value = `int` type tag (or `tag ≥ ERIS_REFERENCE_OFFSET` = backreference id, 2234-2241); permanents = tag `ERIS_PERMANENT`(= LUA_TOTALTAGS+1, :231) + type byte + key. **Self-describing only to that degree; there is NO format version field** — the sole compat affordance is a hack skipping 3 junk bytes when `number_size==0` from old 64-bit builds (u_header 2382-2390). The 5.2 and 5.3 branches already produce mutually incompatible streams (integer flag byte, callinfo layout) and Eris does not care.

**OC dependence on byte layout: none.** `persistence.persist(i)` returns `Array[Byte]` which goes straight to `SaveHandler.scheduleSave(host, nbt, addr+"_kernel", bytes)` and back via `SaveHandler.load` → `unpersist` (NativeLuaArchitecture.scala:407, 412, 362, 369). machine.lua never touches the bytes; jnlua.c's only Eris awareness is the version-string prefix strip (jnlua.c:183-185). A failed/mismatched unpersist raises a Lua error ("invalid data", u_header 2380) which OC's load path converts to its sanctioned crash/reboot. **Conclusion: an API-compatible LuaJIT implementation is free to define its own format** (recommended: reuse the lj_bcdump conventions + a version byte + build-id, refusing foreign streams cleanly).

## (5) Eris issue #4 ("LuaJIT support") — full thread

Read via GitHub API (issue + comments, scratchpad/eris/issue4.json, issue4_comments.json). The thread is short: opened 2013-11-06 by wizzard0 ("Is there a chance this can work with LuaJIT?"); **one** substantive reply by fnuecke (2013-11-06), then closed. No linked discussions in the thread body. Objective technical points raised by fnuecke, exhaustively:
1. **Internals access**: "Eris works on a pretty low level with the vanilla Lua structs (as does Pluto), and uses a ton of non-API macros and functions … I doubt there's much to any similarity there" — i.e., the library as-is cannot work; matches our item (a).
2. **Coroutine representation uncertainty**: whether persisting yielded coroutines is possible "depends completely on how LuaJIT implements those"; he notes Mike Pall "didn't deny the possibility" on the mailing list and *assumes* LuaJIT does not use an OS thread per coroutine. (Resolved above: it doesn't; frames live in the Lua stack.)
3. **Re-jitting**: "a few more hurdles than with vanilla Lua, such as getting the functions re-jitted after unpersisting them" — matches our item (b), and is a non-issue under our constraint (d) (jit.flush + re-warm).
Nothing else was raised — no claim of theoretical impossibility, no GC, format, or licensing objections. Closing verdict was resourcing ("you'd probably be on your own"), not feasibility. Our characterization (hurdles = internals access + re-jitting, plus the then-unknown coroutine layout) is confirmed and complete.

## Verdict: code port vs design port

Measured against eris.c's 2741 lines: roughly **half transfers as near-verbatim code** because it is written against the public API — the settings/registry machinery (~150 ln), endian-safe primitive I/O (~290 ln), simple types (~70 ln), tables/metatables/special-persistence/spkey protocol (~275 ln), permanents + reference/dedup delegators (~220 ln), buffers and the `eris.*`/C API shims (~430 ln). Roughly **a third must be rewritten from scratch** against different structs: p_proto/u_proto (~210 ln → largely replaced by lj_bcwrite/lj_bcread), p_closure/u_closure upvalue linking (~250 ln → GCupval/uvptr/lua_upvaluejoin), p_thread/u_thread (~400 ln → in-stack frame walk, no CallInfo, continuation-address mapping), plus the internals macro layer (~40 ln). Call it **~50-55% reusable lines, but the rewritten third is where all the difficulty lives**, so the honest framing is: a *code port of the protocol/format/traversal layer* and a *design port of the VM-state layer* — with the design (perms substitution, reftable dedup order, spkey semantics, pre-registration for cycles, savedpc-as-offset, upvalue-identity-by-pointer-key) transferring intact, and LuaJIT actually removing two whole Eris subsystems (patched-stdlib continuation perms; CallInfo reconstruction) while adding two new ones (single-allocation proto rebuild via bcread, symbolic mapping of lj_cont_* continuation frames).

CORRECTION: Three nuances, none fatal: (a) "Transfers nearly verbatim" requires a small compat layer — eris_master.c unconditionally calls 5.2/5.3-only API absent from the pinned LuaJIT tree (luaL_len, luaL_tolstring, lua_rawlen, lua_absindex, lua_pushunsigned/tounsigned/optunsigned; ~17 call sites, e.g. lines 376, 388, 919, 966, 990, 1616-1618, 2031, 2420, 2480, 2614, 2642, 2702-2732), all shimmable in a few dozen #define/helper lines; pushtstring/copytstring and the internal alias block must also be redone.
