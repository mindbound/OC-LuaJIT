## v0.5 — ocelot-brain harness *(the development environment)*

Adopted 2026-09-01 after evaluation ([research/ocelot-brain.md](research/ocelot-brain.md)).
**This inverts the previous plan.** v1 assumed the JNI bridge would be validated
in-game; it is validated here instead, and Minecraft is touched only at v1's
final line. The reason is epistemic rather than convenience: this project's
standing weakness is that every verification claim was one step removed from
reality, and this closes that gap for the machine layer — where all the
remaining risk lives. Minecraft was never going to give us a differential
oracle against real Eris. ocelot-brain does. **Superseded -- 2026-10-03:** the ordering was overtaken: Minecraft has been used per fix since 2026-09-16 ([in-game-tests.md](in-game-tests.md) T1-T9; v1's validate-in-the-harness row). ## v1 — Working architecture

The goal: OpenOS boots and runs on the LuaJIT architecture, with the JIT compiler deliberately left off (CCLuaJIT parity: ~1.5–3× vs PUC 5.3, zero trace-safety risk while the plumbing matures). **Superseded -- 2026-10-03:** the interpreter-only stage never happened, which is why "interpreter-only" has left this section's title. The JIT has been on since 2026-09-01: the binding's first OpenOS boot was a JIT-off arm, and it booted with the JIT on the same day, once a CHECKHOOK build dissolved the bogomips hang ([research/jnlua-binding.md](research/jnlua-binding.md)); trace safety is carried by the watchdog (the deadline-hook row below, and v2's adopt-the-watchdog row).

- [x] **HOW THIS SHIPS — RESOLVED, and it is our own `Architecture`, not native substitution** ([research/shipping-model.md](research/shipping-model.md)). Everything proven so far was proven by SUBSTITUTING our native under OpenComputers' own PUC-Lua architecture (`debug.forceNativeLibPathFirst`, which is real in shipping GTNH OC at `LuaStateFactory.scala:200-210`, not just in the harness). **That can never be a product, for a structural reason**: OC reads its config and `System.load`s its native in the same `preInit` (`Proxy.scala:32` then `:74`, with `init()` in each `LuaStateFactory` object's constructor), and we declare `required-after:OpenComputers`, so FML sorts us after it — there is no moment at which our code could set the key. It is also a `debug.*` key a player would hand-edit, has no IMC hook (OC's `IMC.java` offers ten, none for natives), and is destructive rather than additive: our DLL would have to be *named* `libjnlua52-windows-x86_64.dll` and every computer in the world would switch at once with no way back. **Keep it as the benchmark/CI harness — that is what it is for.** The product is `api.Machine.add`, which OC's own source calls out for exactly this: *"This allows providing architectures without implementing a custom CPU item."* Players sneak+right-click a CPU to cycle architectures (`CPULike.scala:28-48`); the choice is stored on the ItemStack and **degrades gracefully if our mod is removed** (`DriverCPU.scala:52-57`); and because OC registers in preInit and we register in init, we can never become the silent default. `OCLuaJIT.java` already registers correctly and `LuaJITArchitecture` already has the `@Architecture.Name` and the required `Machine` constructor. **THREE THINGS THIS ALSO DE-RISKED, each previously an assumption**: GTNH 1.12.58's `machine.lua` differs from the harness's by ONE line in 1548 (`realTime = computer.realTime`); `patch-machine-lua.lua` applies cleanly to the real GTNH kernel (4 sites, exit 0, and it refuses rather than guessing when an anchor misses); and `LuaStateFactory` is a line-for-line port between the two. **ocelot-brain is representative.** Cost of the build-out: of the ten `Architecture` methods, 4 are trivial, 1 small, `initialize` is 20 lines fronting ~823 lines of `ArchitectureAPI` glue, and 4 are hard — `runThreaded` (~107 lines, the yield-classification state machine, and it must self-enforce `Settings.timeout`), `runSynchronized` (a strict stack-shape protocol whose violation crashes the computer), and `save`/`load` (the only parts reaching outside the API, for `SaveHandler` and the internal `Machine.state`). **It is a diff-port, not a from-scratch write**: ocelot-brain's `NativeLuaArchitecture` is ~85% identical to OC's, with OC's original lines left commented above each replacement at all four persistence sites. **Superseded -- 2026-10-03:** no port was written. `LuaJITArchitecture` subclasses OC's `NativeLuaArchitecture` (the v0.5 split row) and overrides only `factory()`, `initialize()` (the kernel swap, next row) and `save()`/`load()` (the `_stack` row); `runThreaded` and `runSynchronized` are inherited (the component-call row). And "everything proven so far was proven by substituting our native" stopped being true that night: AxisOS booted on our architecture on 2026-09-15 (the v0.5 split row), and the smoke suite's persistence milestones moved onto it on 2026-09-16 (the v0.5 run-on-our-architecture row).
- [x] **Watchdog kernel delivery — SOLVED 2026-09-16, by replacing what initialize() loaded rather than how it loads.** `NativeLuaArchitecture.initialize()` loads the kernel from a fixed path in **OpenComputers'** resource domain, and the harness only got its patched kernel in by shadowing that path on a classpath it controls — which a mod cannot do, since FML orders mod jars for us and OC's jar holds that exact resource. Two routes were rejected before the third: **overriding `initialize()` outright is impossible**, because four of its sixteen lines are `apis.foreach(_.initialize())` and `apis` is private with no accessor in either host; and **intercepting `debug.sethook` in the native**, which would need no kernel of ours at all, founders on `machine.lua:47` calling `debug.sethook(coroutine.running(), checkDeadline, "", 1)` — the same function as the three deadline arms with a different count — so telling them apart from C is a heuristic that mis-fires silently where `patch-machine-lua.lua` refuses loudly. What works: let `super.initialize()` do all of its work, then drop the kernel thread it left on the stack, load ours from **our own** resource domain (`/assets/ocluajit/lua/machine.lua`), and make a thread of it again. Six lines. Proven in the harness with the patched kernel present ONLY at our path and nothing at OpenComputers': `_OCLJ_KERNEL=watchdog`, 147 traces against ~2500 under the standing hook, sandbox loop 0.0047 s against 0.47 s, 32 checks 0 failures. The mod-side copy is the same sequence through OC's public `lua()` accessor (ocelot-brain hides it behind `private[machine]`, so the harness reaches it reflectively) and is compiled, not run. (**2026-10-03:** it has run in game since 2026-09-16: the first in-game run row, the `_ENV` row's in-game verification, and T4.)
- [x] **The deadline watchdog MISSED ENTIRELY in 2 of ~6 runs under host load** (`fires=0`: the timer-queue callback was never delivered inside a 15 s window, so a runaway sandbox loop would not have been interrupted at all). A watchdog that is usually on time is not a watchdog; this is a reliability property, not a latency one, and it needs its own measurement before any JIT work leans on it. **Investigated in the harness 2026-09-19 — verdict INCONCLUSIVE, and the investigation found a different, real defect; see the `fires=0` contention row and the caught-timeout kernel-panic row below; the open work is the watchdog-delivery-under-load row.**
- [x] **`d-autorun-counter-live` fixed 2026-09-16 — and it was the boot wait, not the milestone.** It failed in every stock-KERNEL arm (`additive+stock`, `luajit+stock`) with `nonce=<missing>` and `counter -1`. - [x] **M4.4 — function environments diverge from stock Eris. DECIDED 2026-09-19: keep persisting the fenv, always; no serializer change.** Every LuaJIT function carries an fenv and `getfenv(f) == _G` holds even for a closure referencing no global; 5.2 gives such a closure no `_ENV` upvalue at all. (2) In LuaJIT the fenv is real, observable state, not a compiler artefact: `getfenv`/`setfenv` read and write it, and `lj_func_newL_gc` gives every closure created by `f` the fenv `f` had at that moment — so a global-free `f` restored with a substituted environment would hand that environment to every closure it creates afterwards. OC loads all user code with the sandbox table as fenv; the only substitution that could shrink the blob ("fenv equals the writer's `_G`, restore the reader's") is exactly the implicit rebinding perms exists to make explicit and by name, and its failure mode on a mismatched reader is a closure silently reading a different global table.
